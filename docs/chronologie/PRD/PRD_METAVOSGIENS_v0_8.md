# PRD - METAVOSGIENS
## Site agence vosgienne - Version 0.1

**Marque :** METAVOSGIENS  
**Signature :** by KRYST  
**Statut :** PRD fonctionnel initial  
**Origine :** cadrage stratégique v1.0 issu du brainstorming  
**Objectif :** définir le produit, l'expérience et les contraintes du futur site avant conception graphique et développement.

---

# 1. Résumé du produit

METAVOSGIENS est une agence destinée prioritairement aux entreprises du territoire vosgien.

L'agence ne se présente pas comme un catalogue de technologies ou de prestations techniques.

La promesse centrale est :

> **Votre entreprise a un problème ? Construisons la solution.**

Le site doit permettre à un visiteur, qu'il soit artisan, commerçant, indépendant, petite PME ou entreprise plus structurée, de comprendre rapidement :

1. qu'il est au bon endroit ;
2. que son problème peut être pris en compte même s'il ne connaît pas la solution ;
3. que l'agence peut intervenir depuis un besoin simple jusqu'à une problématique complexe ;
4. que la relation commence par un échange humain ;
5. que l'agence est réellement implantée dans les Vosges.

Le site doit rester volontairement compact.

---

# 2. Objectifs business

## 2.1 Objectif principal

Générer des **premiers échanges qualifiés** avec des entreprises vosgiennes.

CTA principal global :

> **Parler de mon besoin**

## 2.2 Objectifs secondaires

- faire reconnaître immédiatement les problématiques auxquelles l'agence peut répondre ;
- rassurer sur la capacité à traiter des besoins simples et complexes ;
- valoriser l'ancrage local ;
- démontrer l'expérience par quelques cas concrets ;
- expliquer la méthode sans jargon ;
- faciliter la prise de contact sans imposer de qualification complexe ;
- constituer une base propre pour le référencement local.

## 2.3 Objectifs non recherchés au lancement

- créer un catalogue de SaaS ;
- vendre des produits standardisés directement depuis la homepage ;
- mettre en avant les technologies ;
- construire un tunnel de qualification complexe ;
- faire du site une plateforme applicative ;
- multiplier les pages commerciales.

- petites PME ;

# 4. Proposition de valeur

## Promesse principale

> **Votre entreprise a un problème ? Construisons la solution.**

## Sous-promesse

> **De votre présence en ligne à vos outils métier, nous construisons ce dont votre entreprise a réellement besoin.**

## Positionnement institutionnel

> **MetaVosgiens conçoit des solutions sur mesure pour aider les entreprises vosgiennes à être visibles, gagner du temps, développer leur activité et faire évoluer leur façon de travailler.**

## Différenciation

- un seul interlocuteur ;
- proximité locale ;
- diagnostic avant solution lorsque nécessaire ;

- capacité à traiter des problématiques complexes ;
- accompagnement dans le temps ;

# 5. Principes éditoriaux

## 5.1 Ton

Le contenu doit être :

- humain ;
- proche ;
- direct ;
- simple ;
- concret ;
- professionnel ;
- sans jargon inutile.

## 5.2 Règle de vulgarisation

Le visiteur ne doit pas avoir besoin de comprendre :

- API ;
- middleware ;
- workflow ;
- SaaS ;
- RAG ;
- architecture ;
- agents ;
- frameworks.

Ces termes peuvent apparaître uniquement lorsque leur compréhension devient utile.

## 5.3 Principe

> **Le problème est le point de départ.**

La technologie est un moyen.

## 5.4 Formulation privilégiée

Utiliser des formulations proches de la façon dont un dirigeant parle :

> « Je fais encore trop de choses à la main. »

> « Mon site ne m'apporte pas assez de clients. »

> « Mes outils ne communiquent pas. »

> « Je voudrais utiliser l'IA, mais je ne sais pas où elle serait utile. »

Éviter les formulations centrées sur les technologies.

> **3 cas**

## 10.2 Cas de référence

### Cas 1

**Processus complexe**

- analyse ;
- traitement ;
- traduction ;
- automatisation ;
- validation humaine.

`Automatisation` `IA` `Data`

### Cas 2

**Acquisition marketing**

- analyse ;
- concurrence ;
- personas ;
- stratégie ;
- contenu ;
- planification.

Repères :

`Acquisition` `IA` `Prospection`

### Cas 3

**Outil métier**

- besoin spécifique ;
- absence de solution standard adaptée ;
- règles métier ;
- données ;
- automatisation ;
- IA.

Repères :

`Application métier` `Sur mesure` `IA`

## 10.3 Interaction

- état initial très court ;
- micro-animation au survol ;
- clic → overlay ;
- retour sans changement de page.

## 10.4 Confidentialité

Respect absolu des NDA.

Ne jamais publier :

- nom de client sans autorisation ;
- logo sans autorisation ;
- capture propriétaire interdite ;
- donnée sensible ;
- résultat chiffré non vérifiable.

Possibilité de mention :

> **Certains projets sont présentés de manière anonymisée pour des raisons de confidentialité.**

# 27. Critères d'acceptation UX

Le produit sera considéré comme cohérent lorsque :

1. un visiteur peut comprendre la proposition principale sans connaître le vocabulaire technique ;
2. un artisan recherchant simplement un site peut immédiatement se reconnaître dans « Être visible » ;
3. une PME avec un problème de processus peut se reconnaître dans « Gagner du temps » ou « Faire évoluer » ;
4. un visiteur qui ne sait pas ce dont il a besoin dispose d'une sortie claire vers le contact ;
5. le CTA principal « Parler de mon besoin » reste identifiable sans être agressif ;
6. aucune interaction n'est obligatoire pour comprendre le site ;
7. le site reste utilisable sur mobile ;
8. les overlays n'impliquent pas de navigation supplémentaire ;
9. la marque et l'ancrage vosgien sont compris rapidement ;
10. le visiteur peut prendre contact sans connaître la solution à son problème.

---

# 28. Critères d'acceptation business

1. La homepage doit présenter clairement une agence destinée en priorité aux entreprises vosgiennes.
2. Le site doit pouvoir accueillir aussi bien un besoin de présence web qu'un projet d'automatisation, IA ou application métier.
3. La création de site vitrine doit rester une porte d'entrée commerciale.
4. Le diagnostic doit être identifiable comme une possibilité réelle.
5. Le premier échange doit rester gratuit.
6. Le site ne doit pas imposer une qualification commerciale complexe.
7. La technologie ne doit jamais être plus visible que le problème client.
8. L'agence doit pouvoir démontrer une expérience réelle sans violer les NDA.

---

# 29. Critères d'acceptation de marque

# 32. Principe directeur final

Le futur site doit donner au visiteur une sensation simple :

> **« Je peux venir leur parler de mon problème, même si je ne sais pas encore ce qu'il me faut. »**

Et donner à l'agence une capacité cachée beaucoup plus vaste :

> **« Une fois le problème compris, nous pouvons choisir et construire la réponse adaptée. »**

> **Simplicité côté visiteur. Profondeur côté agence.**

> problème → compréhension → solution → contact.

> audit → acquisition → automatisation → IA → data → application → POC → MVP → accompagnement.

# 35. Direction couleur validée

## 35.1 Orientation

La palette de marque repose sur un équilibre :

> **Bleu profond + vert territoire + base claire**

## 35.2 Rôle des couleurs

### Bleu profond

Utilisé comme couleur principale de confiance et de structure.

Il doit apporter :

- sérieux ;
- stabilité ;
- professionnalisme ;
- profondeur.

### Vert

Utilisé comme marqueur territorial et accent.

Il doit évoquer subtilement :

- les Vosges ;
- le territoire ;
- la proximité ;
- une dimension naturelle sans devenir touristique.

### Base claire

Blanc cassé / ivoire / gris très clair selon le design final.

Objectifs :

- lisibilité ;
- respiration ;
- chaleur ;
- modernité éditoriale.

## 35.3 Règle

La palette ne doit pas recréer l'identité très technologique de KrystLab.

Éviter une utilisation massive de :

- néons ;
- dégradés futuristes ;
- violet « IA » ;
- glow excessif.

## 35.4 IA

Aucune couleur spécifique ne doit être attribuée à l'IA.

Les éléments IA utilisent les codes de la marque principale afin de conserver une identité unifiée.

## 35.5 Print

La palette doit fonctionner aussi bien sur :

- site ;
- carte de visite ;
- flyer ;
- documents commerciaux ;
- supports locaux.

# 38. Langage visuel territorial validé

## 38.1 Principe

Le territoire vosgien doit être reconnaissable sans être représenté de manière littérale.

Principe :

> **Sentir les Vosges sans voir un sapin.**

## 38.2 Élément principal

### Courbes de niveau abstraites

Les courbes topographiques constituent le langage territorial principal.

Elles peuvent être utilisées :

- dans le Hero ;
- comme éléments de transition ;
- autour des quatre portes d'entrée ;
- dans les overlays ;
- dans les cartes de réalisations ;
- sur les flyers ;
- sur les cartes de visite ;
- dans les documents commerciaux ;
- dans les visuels sociaux.

Elles doivent rester :

- fines ;
- élégantes ;
- abstraites ;
- non touristiques.

## 38.3 Élément secondaire

### Points et connexions

Des points et lignes de connexion peuvent compléter les courbes de niveau pour suggérer :

- relations ;
- flux ;
- données ;
- entreprises ;
- connexions.

Cet élément reste secondaire afin d'éviter de recréer une esthétique « site tech ».

## 38.4 Animations possibles

Le langage topographique peut évoluer selon l'interaction :

- ligne qui se déplace ;
- courbes qui se rapprochent ;
- courbes qui se déploient ;
- points qui apparaissent ;
- tracés qui se recomposent.

Les animations doivent rester lentes, fines et fonctionnelles.

## 38.5 Éléments interdits

Éviter comme éléments graphiques principaux :

- sapins ;
- montagnes illustratives ;
- blasons ;
- cartes détaillées du département ;
- monuments touristiques ;
- circuits électroniques ;
- robots ;
- cerveaux IA ;
- globes ;
- symboles technologiques génériques.

## 38.6 Principe de hiérarchie visuelle

Le contenu reste prioritaire.

Le langage territorial sert à identifier et rythmer la marque, jamais à prendre le dessus sur le message.

Principe directeur :

> **Technologique dans les capacités, territorial dans les codes graphiques, humain dans le discours.**
